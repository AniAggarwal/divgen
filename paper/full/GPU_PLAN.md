## Ground rules

- **Priority is strict**: E1 → E11. Cut from the bottom, never the top.
- **Smoke-test every experiment** at 1 prompt × 2 generations (or 2 iters)
  before the full launch.
- **Watchdogs, not liveness checks**: a run is healthy only if GPU utilization
  is high AND its log tail is fresh. Poll `nvidia-smi` utilization + log-file
  age; restart/diagnose on stalls (see `paper/full/analysis/watchdog.sh`).
- **No hand-typed numbers in the paper.** Every number in both `main.tex`
  files must come from `paper/full/analysis/paper_numbers.json` /
  `stats_results.json` (macros regenerated by `make_numbers_tex.py` /
  `make_figures.py`). Grep-verify each tex value against the JSONs before
  committing.
- If a result contradicts a paper claim, **change the claim, not the result**.
- The papers never use the word "evolutionary" (outside citation titles and
  the disclaimer footnote) and never the name "EvoDiv".
- Terminology in prose: *breeding*, *population-based search*, *artificial
  selection*.
- **Env**: B200 (cc 10.0) needs cu128+ wheels — the preinstalled
  `torch==2.12.0+cu130` is pinned via `/workspace/evodiv-constraints.txt`; pip
  must never touch it. ImageReward's `med.py` needs the
  `transformers.pytorch_utils` import patch before E5. Export
  `PYTHONPATH=/workspace/repos/divgen`, `HF_HOME=/workspace/hf`,
  `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` (all in
  `/workspace/evodiv.env`). Disk is shared with other projects — never delete
  directories we did not create.
- **Uploads are incremental**: as each experiment finishes, tar
  `/workspace/runs/paperprep/<exp>` to
  `s3://anirud-dev/evodiv-divgen-fork/<YYYY-MM-DD>/paperprep-<exp>.tar.gz`
  (helper `/workspace/tigris.sh`) and update `MANIFEST.md` at that prefix.

## Experiments

### E1 — Same-harness gradient baseline (all 553 GenEval prompts)
The repo's own gradient optimizer (`main.py`) with
`configs/geneval_sdxl_white.yaml` (SDXL-Turbo, white noise, DPP+HPS,
lr=6, grad-clip 0.1, 150 iters, B=4), run on **all 553** GenEval prompts on
this B200. Save: final image sets, per-iteration wall-clock (s/iter), and peak
CUDA memory (`torch.cuda.max_memory_allocated`).
*Why*: Table 1's gradient row currently comes from the source paper's own
reporting; a same-harness, same-hardware baseline removes the "different
harness" caveat and gives the timing/memory columns of the efficiency table.
**Paper integration**: replaces/augments the "Harrington et al. (gradient)"
row with a same-hardware row (rescored with the same metric code, E5 also
consumes these images); s/iter and peak-mem enter the efficiency/memory table.
If the same-harness gradient numbers differ from the published row, report
both and compare against ours on the same-harness row.

### E2 — Matched-compute random-search control (553 prompts)
Random search (i.i.d. redraws from the prior, keep the best set under the
identical selection rule: max diversity subject to quality ≥ 0.98 × gen-0
mean) at the **same number of rendered images** as the breeding run consumed
per prompt (read `n_renders` from the archived `geneval_merged` histories;
~9.9k images/prompt). Score with the identical metric code.
*Why*: the paper's claim "any sensible search finds it" needs the null
hypothesis: is structured breeding better than blind luck at equal compute?
**Paper integration**: a "Random search (matched compute)" row in Table 1.
Decision rule: if random search matches breeding, the paper's framing shifts
from "breeding works" to "the landscape is easy" (change the claim, not the
result); if breeding wins clearly, that gap is the selection signal.

### E3 — CMA-DCT at 553 prompts + exact re-scoring
The exploration winner (CMA-ES over an 8×8 low-frequency DCT coefficient
block per channel per slot, 1024 dims vs 65536 = 64× fewer; scalarized
DINO + 3·CLIP) scaled from 40 to all 553 prompts, with **exact re-scoring**
of the final winner (full VAE + full metric suite, `exact=True`).
**Paper integration**: promote CMA-DCT to a headline Table-1 row **only if**
the 553-prompt paired Wilcoxon vs `geneval_merged` is significant on DINO at
p<0.05 without a CLIP loss; otherwise keep the "matches full-space search at
64× fewer dimensions" framing in the text.

### E4 — FLUX.1-schnell (memory-wall demonstration)
Implement latent packing at `evodiv/run.py:_latent_spec` (FLUX latents are
(16, H/8, W/8) packed 2×2 to a (H/16·W/16, 64) sequence; breeding operates on
the unpacked spatial tensor). Run breeding on ≥50–100 GenEval prompts with
the multi-step (4-step) schnell renderer. Produce the peak-memory table:
forward-only (ours) vs gradient (their optimizer) at B=4 and B=16 — the
gradient side may OOM at B=16; report the wall at which it dies.
**Paper integration**: the "Memory" paragraph's FLUX claim becomes a measured
table instead of an assertion.

### E5 — Preference-model judging of E1/E2/E3/archived sets
Score the final image sets of E1 (gradient), E2 (random), E3 (CMA-DCT), and
the archived `geneval_merged` breeding sets with ImageReward, PickScore
(yuvalkirstain/PickScore_v1), and HPSv2.1 — plus the strongest current
successor if one is in common use (evaluation only). **These are never the
bred objective** (user directive: ImageReward deliberately unused in search).
*Why*: rebuts "you optimized CLIP so CLIP is meaningless"; independent judges
none of the methods optimized.
**Paper integration**: a judge-panel table (rows = methods, columns = judges);
paired tests breeding vs gradient. Whatever it says, report it.

### E6 — HPSv2-floored DPP run
Breeding with DPP log-det as the diversity objective and an HPSv2 quality
floor (mirror of the gradient config's Tab-2 setting: DPP + HPS), on the E7/
ablation-sized prompt subset (~40 prompts). Shows the framework handles the
paper's Tab-2 objective pair without a gradient.
**Paper integration**: extends the "Objectives" paragraph with a measured
DPP+HPS row; comparable to E1's config which optimizes the same pair.

### E7 — DPG-Bench subset
Breeding on a DPG-Bench subset (~40 long, dense prompts; the repo ships
`datasets/DPG/dpg_prompts.txt`) with the standard objective pair.
*Why*: GenEval prompts are short/compositional; DPG tests dense captions —
prompt-family generalization of the method, not just the noise sets.
**Paper integration**: one row/paragraph: "the recipe is not GenEval-specific".

### E8 — Vendi long-budget probe
Long-budget (≥150 generations, no early stop) run on ~20 prompts with Vendi
as the bred diversity objective at B=4 (and B=16 if budget allows, cf. the
set-size exploration: Vendi 4.36 at B=16).
*Why*: Vendi is the metric the source paper says saturates; does a longer
selection budget keep buying Vendi, or does it plateau?
**Paper integration**: convergence figure panel + a sentence with the
measured plateau (or absence of one).

### E9 — LPIPS probe
Breeding with LPIPS as the (held-in) diversity objective on ~20 prompts —
LPIPS is our one behind-the-gradient metric in Table 1; test whether
selecting on it directly closes that gap (and what it costs on DINO/CLIP).
**Paper integration**: a sentence in Results resolving the LPIPS deficit
("selectable when targeted" vs "a real limitation").

### E10 — CMA covariance-spectrum dump + transfer band decomposition
(a) Dump the CMA-ES covariance eigen-spectrum per prompt from E3 (or a rerun
at ~40 prompts with `es.C` logging): does search concentrate variance in the
lowest DCT bands, echoing the paper's Fig. 9?
(b) Decompose the archived SDXL→PixArt transfer effect by frequency band:
transfer bred noise low-band only / high-band only / full, measure diversity
delta per band.
**Paper integration**: analysis figure ("where the search happens" +
"what transfers"); both echo the source paper's spectral story with our
machinery.

### E11 — Seed variance (20 prompts × 3 seeds)
The headline pipeline at 3 seeds on 20 prompts (fixed prompt subset,
seeds 0/1/2): per-metric mean ± std across seeds.
**Paper integration**: error bars / a variance note in Table 1's caption ("σ
across seeds < X on every metric"), plus stats file entries.

## Analysis pipeline (`paper/full/analysis/`)

- `aggregate.py` — walks `$EVODIV_RUNS` + `/workspace/runs/paperprep`,
  emits `paper_numbers.json` (every mean that appears in either paper).
- `stats.py` — paired tests (Wilcoxon signed-rank; Holm correction across the
  metric family), emits `stats_results.json`.
- `make_figures.py` — regenerates every figure in `paper/figures` +
  `paper/full/figures` from the runs.
- `make_numbers_tex.py` — regenerates `numbers.tex` macro files consumed by
  both papers; nothing numeric is typed by hand.
- Verification: `verify_tex_numbers.py` greps every macro value in the tex
  against `paper_numbers.json` and fails on any mismatch.
